## 四、生成与几何数学

### 4.1 主树 `buildTree(opt)`（单位系：干长 1、基点 `(0,0)`、向上 `−y`）

纯函数 ⇒ 逐字段可对账，Kotlin 侧同名同序即可 1:1 移植。返回 `{segs, snow, clumps, bbox, maxRatio, truncated}`。

- **递归** `grow(x,y,ang,len,wid,depth)`：`depth ≤ 0` / `len < 1e-4` / `segs ≥ maxSegs` 三路终止；
  第三路置 `truncated`（⛔ 静默截断会让档位差异被误读成"种子变了"，HUD 与 `B.treeStats` 必须暴露它）。
- **弯曲**：控制点 = 中点沿法向偏 `(rnd·2−1)·bendK·len`；每段用二次贝塞尔离散为 `n` 个子段，
  `n = clamp(round(len / segLenPx), 2, 6)`，子段宽度 `wid·(1 − 0.45t)`。
- ⭐ **`segLenPx` 必须是单位系量**：`treeOpt()` 里 `segLenPx = segPx / max(1, L.treeH)`（目标像素长子段 ÷ 树高）。
  直接喂像素常数 26 会让 `n` 恒被钳到 2 ⇒ 整树只剩骨架（P1）。
- **承雪判据**：子段切向水平度 `horiz = |ux|`（1 = 全水平）。仅 `horiz ≥ snowHMin(0.42)` 的子段产雪，
  雪宽 `sw = max(snowMin, w · snowK · (0.35 + 0.85·face))`，`snowMin = 0.0042`（单位系绝对值）。
  ⚠️ **下限必须是绝对值，不能是枝条比例**：`sw ∝ w` 时粗细枝的「雪/枝」比恒等 ⇒ 细枝永远埋不进雪，
  上冠长出一蓬露在雪外的黑铁丝（P12）。
- ⛔ 偏移方向**恒为屏幕向上 `−y`**，量值随水平度 ⇒ 绝不沿法向偏移（陡枝两侧挂雪读成"冰凌"不是"积雪"；
  T3 用竖直度做负样本，平均水平度从 0.797 掉到 0.486 即被抓）。
- **埋没度**：`bury = clamp((0.0090 − w)/0.0060, 0, 1)`，雪脊上偏量 = `sw·(0.62 − 0.45·bury)`
  ⇒ **粗枝留"上侧承雪"的偏置、细枝被雪居中包住**（真物理：1 px 的末梢埋在 5 cm 雪下是不可见的）。
- **枝干明暗斜坡方向**：`thin = clamp((3.4 − depth)/2.4, 0, 1)`，颜色向 `(214,219,226)` 插值 `thin·0.86`、
  alpha 乘 `(1 − 0.46·thin)` ⇒ **越细越淡**。⛔ 反向（P13：旧写法末梢比树干还黑 ⇒ 整树读成一团铁丝）。
- **子枝**：`kids = 2 + (rnd < childP3 ? 1 : 0)`，角度 `ang + side·spread + 抖动`，
  **下垂项** `droop` 同时按「水平位移符号」和「|side|」两项施加 ⇒ 越靠外越低，长成"被雪压弯"的伞形。
  子枝长度比 `kl/len = lenDecay·(0.86…1.16)`，`maxRatio` 被记录用于 T2 的单调性判据。
- ⭐ **雪脊（`clumps`）= 沿枝方向的条状积雪**（D13，第四轮改的；⛔ 旧口径叫"团雪"）：
  每条 `clump` 带 `{x, y, r, depth, tx, ty}`，`tx/ty` = **该处枝条切向**，烘焙期整组几何旋进这个方向。
  来源两处：**枝端**（末子段 55% 概率，取该子段的弦向）+ **每条子枝根部**（`hash2 < 0.62`）。
  ⭐ 根部脊的 `tx/ty` 与中心**必须取自子枝"实际画出来的第一段"**（`segs[s0]` 的弦向与中点），
  ⛔ 解析发射角 `a` —— 枝条是贝塞尔弯曲的，`a` 只是起点切线，`bendK` 能让第一段与它差到
  ±`atan(2·bendK)` ≈ 31° ⇒ 按 `a` 摆的雪脊读成"雪挂歪了"（T3 的脱枝判据实测抓到 269 条里 29 条，P29）。
  ⛔ 母枝节点上那坨按**母枝宽**给的无方向团（`r = wid·1.4`）已删——它把体积堆在"节点"这个最不该积成一团的地方
  （P28）。每脊渲染 = 三瓣底（宽淡）+ 三瓣顶（实心）+ 三个 hash 小瘤（破"棉花糖"轮廓，P14 的修法保留）
  + 一条**沿枝方向**的下缘冷灰描边。
  ⚠️ **旋转必须吃各向异性缩放**：位图映射里横向 `sx = uy · crownW`（冠幅独立可调，`crownW=1.16`），
  所以单位系的单位切向量 `(tx,ty)` 到像素系要转成 `atan2(ty·uy, tx·sx)`；写 `atan2(ty, tx)` 会让所有雪脊
  **系统性偏转**（冠越宽偏得越多，细枝上直接读成"雪挂歪了"）。
  ⚠️ **根部那一次抽取 `rnd()` 的次序是几何的一部分**：见 P28 ③（删一次抽取 = 换一棵树）。
- **基部两层**（画在树位图自己的最上层）：先 2 团**比雪裙更宽**的冷阴（树坑 + 接触投影，
  `createRadialGradient` 内半径留 12% 空洞 ⇒ ⛔ 压黑树干），再 4 团雪裙盖住树干下缘。
  ⚠️ **顺序不能反**：先白后暗会把整圈糊成一摊水渍（P15）。
- **位图映射**：纵向 `uy = L.treeH / bbox高度`（**冠高精确落到 `L.treeH`**），横向 `sx = uy · crownW`（冠幅独立可调）。

### 4.2 雪原表面线与地平线裁线

`snowSurfaceY(x) = hz + H·(0.012 + 0.030·fbm(5.5u, 3.7, 3, 0.5, 2) + 0.010·sin(5.1u))`
—— 雪粒的**消隐边界**跟着它走（落到雪面即从顶部重生 ⇒ 粒子数守恒，T4），⛔ 用固定 `y=H` 会让雪穿坡。

⭐ **地平线上那条"尺子线"不是任何一条画出来的线，而是 `ground` 位图自己的直边上缘**
（`drawGround` 从 `hz − H·0.02` 起整幅 blit）。所以修法只能在烘焙期做：
① `destination-out` 沿 `snowSurfaceY(x) − H·0.012` 填一条波浪上方区域 ⇒ 位图上缘变成波浪线，
松林与远景雾带一直露到雪面；② 再沿这条切线补 26 坨**中心压在切线上、上半溢出**的碎雪堆
（压扁的径向渐变，⛔ 描边椭圆）⇒ 地平线是"堆出来的"，不是"画出来的"（P16）。

### 4.3 风的形变表 `meshTable(sway, rows, cols)`

行中心归一化高度 `u = (yBot − yc)/span ∈ [0,1]`（底行 = 树干着地处 = 0），
偏移 `off = sway · u^1.6`，**同行所有列写同一个值**。于是：底行恒 0（树根不许飘）、沿高单调（越尖越晃）、
横向不可能撕裂（T9 三条判据 + 「逐列独立填表」负样本，最大列间差 13.99 px 即被抓住）。
Kotlin 侧这张表就是 `drawBitmapMesh` 的顶点 x 位移，**1 次调用**。

### 4.4 雪粒五层与 `land` 景深语义

```
LAYERS = [ {f:0.30,r:1.05,a:0.30,share:0.28 ,rgb:'224,231,241',shape:'dot'   ,land:0.06}   // 极远
         { f:0.50,r:1.60,a:0.52,share:0.27 ,rgb:'236,242,250',shape:'dot'   ,land:0.17}   // 远
         { f:0.76,r:2.45,a:0.78,share:0.25 ,rgb:'247,250,254',shape:'dot'   ,land:0.36}   // 中（≈树基深度）
         { f:1.00,r:3.10,a:0.97,share:0.165,rgb:'255,253,248',shape:'streak',land:0.92}   // 近（带拖尾）
         { f:1.42,r:11.0,a:0.135,share:0.035,rgb:'255,252,246',shape:'bokeh',lens:true,land:1.0} ] // 前景虚化
```

- ⭐ **`land` = 该层雪粒落在雪原上的"深度"**（0 = 地平线、1 = 画面底），消隐 y 由它算出：
  `yLand = hz + (H−hz)·land + 0.5·(snowSurfaceY(x)−hz) + r·S·0.5`。
  它同时决定**绘制顺序**：`land` 小于树/人深度的层（L0/L1）画在树**后**，L2 与树基同深度画在树**前**、
  人**后**，L3/L4 压在最上 ⇒ 雪有了前后遮挡，才读得出"漫天"而不是一层白点贴在画面上（D9）。
  ⛔ 五层共用一条 `y=H` 消隐线 ⇒ 下半屏永远没有雪落在地上（P17）。
- **`shape` 三态一套代码**：`dot`（`k=0` 零长线 + `lineCap=round` 自动是圆点）/ `streak`（近层拖尾）/
  `bokeh`（前景虚化：半径 11、alpha 0.135、`lens:true` ⇒ 只有 3.5% 的粒数承担"镜头上有雪"的前景纵深）。
- **逐粒半径抖动** `snow.rVar`（LOW 0.34 / MED 0.42 / HIGH 0.46）⇒ 同层内大小不一，⛔ 同层等径读成"印刷网点"。
- 速度 `vx = windPx·f·(1+sway(t,ph))`、`vy = fallPx·f·(0.85+0.30·sin(ph+1.3t))`；水平翻转 `±1.07W` 循环。
- ⭐ **拖尾长度 `k = streak · (2r)`，即「streak × 直径」，只给近层**；⛔ 用「速度 × 秒数」——
  长度随风速与分辨率一起漂，近层会被拉成 10×30 的药丸（P2）。三层/五层共用同一段代码，
  ⛔ 两份实现（T5 计数的就是逐帧这段，两份必漂移）。
- **冰晶闪光**（`fx.glint`，LOW 34 / MED 56 / HIGH 78）：雪面上 1 条 Path 一次 `fill` 的菱形微亮，
  相位由固定子种子 `0x77a1` 派生 ⇒ ⛔ 逐帧随机数（会闪成噪点）。

### 4.5 人物 = 站定剪影 + 肩雪盖（D8 → D10 → **D11 照参考图重画**）

**两张位图、各 1 次 blit、位置恒定。** `bakePerson()` 烘 `B.person`（深色本体）与 `B.personSnow`
（浅色积雪）两张**同尺寸同锚点**的位图（`w = 0.78·hh`、`h = hh + 16`、`top = 8`、
`soleY = top + hh·0.9995`），逐帧由 `personRect()` 算出同一个矩形：先 blit 本体，再在
`PR.dust > 0.004` 时以 `globalAlpha = PR.dust` 叠上肩雪盖。⛔ 没有姿态数组、⛔ 没有朝位、⛔ 没有步态相位。
`top` 留 8 px 是**必需**的：积雪的中心压在轮廓线上 ⇒ 必然有一半露在轮廓外，`top=3` 会把帽顶雪切掉。

- **⭐ 与树同一条水平线（D11 / 所有者第三轮裁决）**：`P.comp` 里**没有 `personY` 字段**，
  `layout()` 直接 `L.personY = L.treeBaseY`。留一个字段就是留一条会漂移的路。
  T12 两头堵：`sameLine` 要求 `L.personY === L.treeBaseY` **且** `P.comp.personY === undefined`，
  负样本 `negLine` 把树基 +0.02H 再比一次 ⇒ 谁把 `personY` 恢复成独立参数，本条当场红。
  同线 ⇒ 同人同深度 ⇒ 身高按真实比例回到 `personH = 0.090H`（树 0.62H ≈ 12 m ⇒ 1.75 m 人 ≈ 0.090H；
  上一版为把人"往前放"给的 0.086 是配套的补偿，⛔ 同线后还留着那个数）。
- **本体 18 块**（`drawPersonPose`，全部走 `limbPath` 锥形多边形 + `pkDisk` 圆盘，每块 `ink()` 实心 +
  round-join 同色描边 ⇒ 相邻块**融成一条连续外框**）：远腿 / 远靴(2) / 远臂 / **远手套** / 大衣(5 关节) /
  **肩线 yoke** / 围巾 / 头 + 帽(4 盘) / 近腿 / 近靴(2) / 近臂 / 手套 / **手杖**。尺寸全是 `hh` 的比例常数，
  ⛔ 不吃逐帧随机数 ⇒ 同一姿态每次逐位一致（T11 因此可以量面积）。
- **⭐ 全部部件 alpha 恒 `1.00`**（P23）。混用 0.90/0.96/0.97 时重叠处会叠出更深一档的色块，
  在真实尺度（≈65 px）上读成"身上挂着破布"——**第一轮返工观感没变的根因就在这里**，不是轮廓画错。
- **比例照所有者选定的参考图逐线量出**（占身高）：帽顶 0 · 下巴 `chin=0.145` · 肩线 `sh=0.192` ·
  腰 `hip=0.420` · 衣摆 `hemB=0.510`（**是夹克不是长大衣**，旧版 0.562 直接把腿埋了）· 膝 0.755 · 踝 0.954
  ⇒ **6.9 头身**；解剖肩半宽 0.117（= 肩峰 0.104 + 带宽 0.013）、髋半宽 0.090 ⇒ 肩宽于髋。
- **⭐ 斜肩必须由独立的 `yoke` 多边形承担**（P27）：`limbPath` 在关节处的端面恒**垂直于中轴**，而躯干中轴在肩段
  几乎竖直 ⇒ 肩半宽给到 0.112 只会得一条**水平平板**（读成防弹衣 / 圣诞偶）。改法：躯干肩关节半宽降到 0.070
  （只当中轴的锚），另画一条中轴**横向走**的 `yoke`（领根 0.184 → 肩峰 0.206，坡 ≈12°）——它的端面是竖切 ⇒
  上沿自然斜下来。`shoulderTop(pose)` / `shoulderHalf()` 从 yoke 现算，⛔ 手抄肩线 y 值。
- **近侧臂斜下去扶杖**：垂直贴身时手臂内沿整个嵌进大衣 ⇒ 上身读成一口钟，"有胳膊"完全看不出来；
  斜到杖上后腕部内沿 0.136 > 同高衣摆外沿 0.116 ⇒ 身侧露出一道**楔形空隙**，那是剪影里读得出"手臂"的唯一线索。
  肩关节 x 取在**肩峰正下方**（0.117 − 0.030 = 0.087）：⛔ 取 0.100 时手臂外沿 0.130 比肩峰还宽 ⇒ 肩端各出台阶，
  读成翅膀/肩章。
- **手杖 = 全身唯一的硬斜线**：`cane [[0.168,0.524],[0.206,0.9985]]`，柄压在近侧手套底下、杖尖与两靴底同线、
  整条落在右腿外侧（⛔ 与腿重叠 ⇒ 读成三条腿）。它同时是"为什么站着不动"的物理交代。
  ⚠️ 细件必须 `ink(…, swMul 0.30)`：融接描边宽 `hh·0.022` ⇒ 每侧外扩 0.011 hh，而杖的半宽只有 0.010 hh
  ——不吃这一项杖会被描边加到 2 倍粗，真实尺度上读成一块门板（P26 的一部分）。
- **前后景靠"略窄"分离，⛔ 靠半透明**：远侧腿 ×0.94、远侧臂 ×0.88。
- **头/帽 = 颅 + 下颌 + 帽檐 + 帽顶四块圆盘**（⛔ 一整颗大椭圆再扣一顶更宽的帽 ⇒ 灯泡头）。本版檐宽 = 颅宽
  （0.050 = 0.048 + 描边余量，针织帽折边本来就与头等宽），帽顶收成 0.042 且**平顶**（ry 只有 0.020）。
- **接触暗影只画一整条**（`rgba(150,162,178,0.26)`，`rx 0.205 / ry 0.019`，压在两脚**与杖尖**之下，
  `PKON=false` ⇒ ⛔ 不计入剪影体量）。⛔ 三只脚各一片 ⇒ 中间露出没压住的灰边（读成"脚下垫了块毯"）。
  雪原上那一圈被踩陷的窝（`bakeGround` 里的暗壁 + 亮心）半径同样从 0.195 提到 **0.215**，⛔ 杖尖落在窝外。
- **肩雪盖 = 帽顶 1 盘 + 沿肩线一条不断开的带 + 手套背 1 盘**（`drawPersonSnow`）。两个硬约束：
  ① 每片的**中心压在轮廓线上**（上半露在天光里、下半盖在黑形上）——⛔ 整片落在深色形体内部，
  那读成"衣服上贴了块白斑"（P26 真因 ⑤）；② ⛔ 左右各一片：中间必露出大衣上缘 ⇒ 读成白领 / 企鹅（P25 真因 ①）。
  领窝处带宽收成 0.005（那里是脖子，堆粗了就把颈窝糊掉 ⇒ 又变回蘑菇）。落点全部由 `shoulderTop(pose)` 导出。
- **`PR.dust`（唯一的时变量）**：`sh = max(0, (gust − shakeAt)/(1 − shakeAt))`，
  `dust += dt/dustSecs − sh²·dt·shakeRate`，clamp 到 `[0,1]`；`person = { dustSecs: 14, shakeAt: 0.72, shakeRate: 1.4 }`。
  ⚠️ 三个数是配出来的：`gust` 是 17 s / 41 s 两个正弦的和，**约四成时间都在 0.6 以上** ⇒
  原先的 `shakeAt 0.55 / rate 2.6` 让抖落项全程压过累积项，肩雪**恒 0**（t=40 实测 dust=0），"雪落肩"根本看不见。
- **判据为什么是「填框率 + 宽占比 + 绝对宽度」而不是「绝对体量」**：剪影的 bbox 由**关节**决定，
  把肢体半宽砍到 0.26× 时 bbox 只窄 8% ⇒ 宽度占比**不可能**区分火柴人；而"绝对体量 ≥ 0.25"这条
  是照上一版渲染色抄的（0.259 vs 闸门 0.25，只有 3.6% 余量），且 `体量 ≡ 填框率 × 宽占比 × 高占比` 是**恒等式**
  ——它没有携带任何填框率与宽占比之外的信息，削掉桶腰后必然变红（详见 P26 与 §九 D12）。
  现行 T11 的**正向**判据共 11 条：`ratio ≥ 0.60`、`hFrac ≥ 0.96`、细线版 `mass ≤ 0.40×` 且 `ratio ≤ 0.55×`
  （后两条把"火柴人"直接写进正判据里），加上**七条结构判据**——颈（`neckOK`：可见颈长 ≥ 0.018 且领宽 ≤ 肩的 30%）、
  腰（`waistOK`：腰 ≤ 肩的 85% 且摆 > 腰）、臂（`armOK`：肘外溢 ≥ 0.015）、头（`headOK`：`chin ≤ 0.150` ⇒ ≥ 6.7 头身）、
  杖（`caneOK`：有一根 `x1 ≥ 0.160` 且 `h ≥ 0.40` 的长条）、宽（`widthOK ≥ 0.30`，由点表声明的 0.333 取 90% 推得，
  ⛔ 抄测量值）、解剖（`anatomyOK`：肩/大腿/上臂/靴四条**绝对半宽下限**，读 `PERSON` 表本身）。
  **负样本另计七个**（桶 / 蘑菇 / 无臂 / 大头 / 无杖 / 窄框 / 火柴），每个只咬自己那一条。
  ⚠️ 面积**不另写公式**：`limbPath`/`pkDisk` 在 `PK` 非空时把**实际消费的顶点**采集下来（12 边近似，误差 1.3%），
  两份几何必漂移。
- 真实尺度提醒：1280×720 下人 **≈65 px 高**（`personH = 0.090H`）⇒ 1280 宽缩略图上判读人物细节毫无意义，
  必须用驱动的 `zoom` 最近邻裁块（§十三）或 `poses 420` 放大表看。


## 五、逐帧图元预算（TV 安全线）

真机基线（记忆 `project-baseline-tv-hwui-limits`）：创维 API 22 的 SIGSEGV 触发器是
「大量互不相连的小矩形 + 无全屏操作」⇒ 合并大基元安全。本效果的合批三处关键：

| 图元 | 原型（浏览器） | **Kotlin 侧** |
|---|---|---|
| 天幕 / 调色 | 各 1 次全屏 blit | 各 1 |
| 模糊日晕 | 2 次径向渐变 fillRect | 2 |
| 阴云层 / 吹雪雾带 | 每条带 2 次 blit（平铺补右缘） | **`ImageShader(TileMode.Repeated)` ⇒ 1 次/带** |
| 远景松林 | 1 blit | 1 |
| 雪原 | 1 blit | 1 |
| **主树风摆** | `rows` 次切片 `drawImage` | **1 次 `drawBitmapMesh`**（rows 行顶点） |
| **雪粒（`dot` / `bokeh` 层）** | 每层 1 条 Path + 1 次 `stroke()` | **每层 1 次 `Canvas.drawPoints`**（五层共 5 op） |

## 六、音频映射（纯氛围克制，所有者选定）

只吃**律动通道**（线性 `bass/mid/treble/energy`），⛔ 不吃 gamma 显示通道 `spectrum`（AudioFrame 铁律）：

| 源（经 `AudioSmoother`） | 目标 | 公式（原型 §7 `worldState`） | 系数 |
|---|---|---|---|
| `bass` | **风压**（雪斜着飞的量） | `kWind = kWind₀ · bass`，`wind = base·(1+kWind)·(1 + gustAmp·(0.5+kGust)·gust)` | `0.80` |
| `energy` | **阵风深度**（横扫幅度） | `kGust = kGust₀ · energy` 乘进阵风项；同时 `fallPx·(1+0.35·kWind)` 让落速随 bass | `0.90` |
| `bass` | **树枝摆幅倍率** | `swayMul = 0.45 + 0.55·bass` ⇒ 无声时仍有 45% 摆幅（⛔ 静音即静止） | — |
| `treble` | **日晕亮度** | `sunGain = 1 + 0.35·kSun`，`kSun = kSun₀·treble` | `0.60` |

平滑：`k = 1 − exp(−smooth·60·dt)`，`smooth = 0.085`（E44 T9 同族做法）。
⛔ 不做：频谱柱、节拍闪光、几何随 beat 形变、雪花随拍点 spawn。
**T8 实证**：无声 900 帧后 `max|Δk| = 4.8e-34`、`ΔswayMul = 0` ⇒ 无声帧逐像素等于静态定稿帧；
有音 90 帧 `max|Δk| = 0.1058` ⇒ 映射确实活着（不是接了根死线）。

  ⇒ 等于把缺陷的体积当成了标准。修法：删掉体量下限（保留**记账**，§十 仍打印），补两条**能独立咬人**的正判据
  `widthOK`（宽占比 ≥ 声明轮廓宽 0.333 的 90% = 0.30，⛔ 抄实测 0.359）与
  `anatomyOK`（肩/腿/臂/靴四组半宽各自 ≥ 解剖下限），并**同步补两条负样本** `negNarrow`（整体收窄 0.10）
  与 `negStick`（半宽 ×0.26 ⇒ 肩 0.030 < 0.095）。
  结果：T11 的**正判据**从 4 条（体量 / 填框率 / 高占比 / 块数）换成 11 条（填框率 / 高占比 / 细线版体量与填框率双上限
  + **七条结构判据**：颈 / 腰 / 臂外溢 / 头身 / 杖 / 宽占比 / 解剖半宽），**负样本**从 2 条升到 **7 条**，
  ⛔ 判据只变多变强（被删掉的"块数 ≥ 15"由"18 块"的实测值继续记账，⛔ 再当闸门——它只数得多、判不出对错）。
  教训一般化：**判据红了的正确反应是证明"哪一维在说谎"，⛔ 是把那一维的数调小。**
- **D13 积雪的方向语义 = 一律沿枝条切向，⛔ 任何轴对齐的团**（所有者 2026-10-14 第四轮裁决）：
  原话「大树的各个分叉节点，雪体现的是一个大团，成椭圆了。这是不对的，应该还是按树枝的方向落雪，类似普通树枝一样」。
  这条**不是"把节点团调小调扁"**，而是把"分叉处的雪从哪来"这个问题重答一遍：真树上没有"节点雪"这种东西，
  只有**每条枝自己上表面的一条雪脊**在根部彼此相接 ⇒ 于是体积由子枝生成、母枝节点不再独立产雪。
  由此立下一条**覆盖全树**的不变量（K2/K3 移植时同样受约束）：`clumps` 每条**必须**带 `tx/ty`，
  渲染期整组几何（瓣 / 小瘤 / 下缘描边）旋进该方向；新增任何"积雪"类图元都走同一契约，
  ⛔ 出现 `ellipse(..., rotation=0, ...)` 这种轴对齐摆法即视为回归。
  ⭐ 这条不变量**有闸门**：T3 从"只管承雪水平度"扩成"**＋ 每条雪脊长轴必须贴住某条枝段**"
  （判法 = 从 `segs` 独立反解：存在一条枝段，其弦向与脊长轴夹角 ≤ 22° **且**脊中心到该弦垂距 ≤ 自身半径；
  负样本 = 把全部脊的长轴抹平成轴对齐 ⇒ 实测脱枝 **180/266**）。
  ⚠️ 加这条闸门**当场抓出一个真缺陷**（P29：29 条脊按解析发射角摆、与弯过的枝条对不上），
  也就是说 D13 落地时**画面本身还是错的**——⛔ 只写规则不写判据，规则会在下一次改动里静默失效。
  ⚠️ 派生的两个易错点已写进 P28：像素系旋转角要吃各向异性缩放（`atan2(ty·uy, tx·sx)`）；

## 十三、原型使用说明

**浏览器**：直接打开 `docs/archive/e47-snow-cedar-preview.html`（1600×900 canvas），点画面开门禁后出右栏与 HUD。
**30 个滑杆 + 1 个档位选择器**，分七组：构图锚点（`hz`/`treeX`/`treeY`/`top`/`crownW`/`sunX`/`sunY` 7 条）、
