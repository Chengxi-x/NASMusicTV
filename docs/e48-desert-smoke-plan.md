## 一、需求（所有者原话拆解）

> ⚠️ 本节曾与 §4.3/§4.4 的"已删除"记录并存而读者无法判断哪个是当前。现已按第三轮裁决对齐，
> 并在下方「所有者已裁决 / 已改写」块里逐条标出**哪些条目是被改写的**（⛔ 不静默改）。

1. **体现「大漠孤烟直」的效果** —— 这是本主题的**第一读感**。画面主体不是沙丘，是**一根烟柱**：
   它必须**直**、必须**孤**（全画面只有这一条竖向元素），并且**看得出来源**。
   ⭐ **来源的表述已改写**（第三轮）：所有者删掉烽燧后，"来源"不再是**一个可见的火口**，
   而是**烟根暖光只在沙脊上沿漏出的一团暖色** + **烟柱从脊线之后升起**（`smokeBaseY` 压在源层画布顶边之下，
   由图层序吃掉根部）。见 §九 **D11**。
2. **要有一条孤烟直上，烟要有轻微的摆动** —— ⚠️ 两个量词都是硬约束：
   「**一条**」⇒ ⛔ 多股、⛔ 分叉（柱顶曾经分叉成 Y，P2）；
   「**轻微的摆动**」⇒ 摆是**整柱协调地倾**，⛔ 逐粒乱抖（那读成"抖动"而不是"摆动"，P3）。
   定量口径：柱顶最大水平位移 ≤ **0.026 W**（T2）、柱切线倾角 ≤ **6°**（T5，第三轮随几何收紧，
   理由见 §八 P12 与 §九 D11）、实测最坏位移 **0.0178 W**、最坏倾角 **5.4°**（音频摆幅饱和 1.5× 下的最坏值，§十）。
3. **见参考图**（红日 / 沙丘）—— 取三条母题：① **低垂的巨大落日**，下缘被**远脊切断**（不是悬空圆盘，
   也不是沉到地平线以下）；② **多层沙丘**（**深度排序的重叠脊**，由 `buildDunes()` 按 `(seed, n, sub, stack, ovl, gapK)`
   **生成**成 5–9 层，⛔ 不是四条手写脊线，见 §4.1 / D13）；③ **无云暖红天空**
   （⛔ 云、⛔ 蓝紫透，只有极淡的横向拉丝纹理）。
4. **追加元素（所有者在 brainstorming 中点名，第三轮已删两项）**：
   - ❌ **烽燧 / 烟墩剪影** —— **已删除**（第三轮，原话「下面不要烽火台，不好看」）。
     替代实现 = **烟根暖光**（`drawEmber`，贴在源层脊线之下，随后被该层画布盖掉大半，
     **只在脊线上沿漏出一团暖色**）+ 沙脊遮挡。⛔ 不画台子。
   - ✅ **远处驼队** —— 「驼队不是静止的，应该**从一边走到另一边，偶尔出现**」⇒ 必须**横穿**、必须**偶发**
     （T10：1800 s 内 12–20 波、波间空窗 ≥40 s；实测 **15 波 / 空窗 [40.3, 79.0] s**，§十）。
   - ❌ **长河 / 水面反光** —— **已删除**（第三轮，原话「不要水面了，区分不开」）。
     ⇒ 「大漠」配「长河落日圆」的文学母题与画面那条**水平高光带**一起放弃；
     ⛔ 不得以"沙地反光"的名义把水面效果换个名字加回来（连带后果见 §八 P17）。
5. **驼队的遮挡语义** —— 「脊线后露头，**腿被沙丘挡住**」⇒ 遮挡**只能来自图层顺序**
   （驼队画在自己所在画布**之前**，随后那张画布的 blit 把腿吃掉），⛔ 用"干脆不画腿"糊弄

   定量：峰高露出比例 ∈ **[0.40, 0.85]**（T9）。
6. **烟的形态 = 细直白烟 + 落日逆光暖边**（所有者在三个选项里选定）。
7. ⭐ **真实度令（所有者原话）**：「我担心用圆环或圆来画烟，可能会效果不好，不真实，这个你把握吧。继续」

## 二、可行性结论

**可行。** 四条依据：

1. **渲染通道已验证**：E43 海边 / E44 明月 / E46 迷雾 / E47 雪松均为 Compose Canvas 2D + `nativeCanvas` 直绘，
   已在创维 API 22 真机验收。本效果用到的原语只有 **位图 blit（含旋转贴图）、单条 Path 描边、
   径向/线性渐变 fillRect / arc.fill** —— 无一种新原语，且**不需要** mesh（约束 ②，理由已换成预算模型）。
2. **形态可以纯数学生成**：沙丘脊线是**解析函数** `crest(i,x)`（§4.1）⇒ 烘焙、遮挡、自检、驼队脚线、
   烟根锚点、layout 极值扫描**共用同一口径**（这条"同口径"已从 §4.1 的一句注**提升为 K2 的验收标准**）；
   烟丝是 12 张 128×128 位图（6 变体 × 中性/暖边）；驼队是 6 帧步态剪影表。零外部素材、零模型文件。
3. **原型已实证**：**14 条**自检全绿且**每条带会咬人的负样本**（故意改坏必须变红）；
   harness 5400 帧推进 NaN/Inf=0、`u` 越界=0。
   ⚠️ **但"全绿"只覆盖几何/算术，不覆盖读感** —— 详见 **§八之二**。
4. ✅ **预算有真机背书，且现在由断言看守**：HIGH 档铺屏 **3.91 屏** / 原型 96 op（Kotlin 折叠后 94），
   低于 E44「明月」**已验收**的 4.21 屏 ⇒ **余量 0.30 屏（7.6%）** ⇒ 本主题**不需要** E47 那种"超预算 +21% 待裁决"的豁免。
   ⚠️ 余量**很薄**：第四轮放大日盘时一度只剩 0.079 屏（1.9%），靠日晕改按绝对像素收窄（P26）救回。
   ⇒ 阈值已固化为 harness 的 **B1/B2/B3 三条预算上限断言**（进 `process.exitCode`），
   任何"再放大一点某个元素"的需求都会**当场变红**，而不是悄悄退化成 E47 式的"超预算待裁决"（D13 的双杠杆拆分就是为这条服务的）。

⚠️ **内存口径已更正两处**（第一版写错，移植者会照抄）：
- ⛔ **`grade` 不能用 `RGB_565`**：`bakeGrade` 写的是 `d[k+3]`（**有 alpha**），565 会把半透明暗角压成不透明
  （直接吃掉天幕）或者退化成黑块。
- ⛔ **`sky` 建议 `ARGB_8888`**：它现在是**全屏 5 锚点平滑渐变**，565 在电视面板的 8-bit 输出上会出现可见色带；
  若必须省内存 ⇒ 565 **必须配 dither**。
- 其余不透明层（沙丘画布）可用 `RGB_565`；`wisp*` / `camel*` / `veil` 必须 `ARGB_8888`
  （565 无 alpha 会把烟丝啃出锯齿）。

⚠️ 内存为**推算口径**（K3 须以实测取代）。1080p / HIGH 的量级推算（**每个字节数都可由上表的尺寸现算**，
不是实测）：

| 沙丘 9 张（Σ高 ≈ 0.66 H） | 1920 × ≈713 | ≈ 5.2 MiB |

## 四、生成与几何数学

### 4.1 多层重叠沙脊（⭐ 整节已按第三轮重写；旧「四条脊线」表作废）

> ⚠️ **作废说明**：上一版的 `ridge / far / mid / near` 四行硬编码表（各自基准 y / 振幅 / `f1` / `f2` / 相位种子）
> 已被 `buildDunes()` 的**表生成**取代。裁决原话是「要有很多沙丘重叠，**⛔ 三道线**」——
> 根因不只是层数少，更是**每层的脊形太圆**（fbm 是"山丘"，参考图里的沙脊是**刀背状折线**）。

```
ridgeAt(x, y, p) = (1 − |2·fbm(x, y, 3, 0.5, 2) − 1|)^p        // ridged 噪声的一维版：峰尖、谷平
ridgeMix(c, u)  :                                       // 第 i 道脊在归一化横坐标 u 处的脊形（0…1）
  a = u·c.f1 + c.s          b = u·c.f1·2.1 + c.s·1.9
  rg = 0.78·ridgeAt(a, c.s+3.3, c.sharp) + 0.22·ridgeAt(b, c.s+7.1, c.sharp·0.62)   // 两个八度：大脊套小脊
  hl = 0.78·fbm(a, c.s+3.3, 3, 0.5, 2)   + 0.22·fbm(b, c.s+7.1, 2, 0.5, 2)           // 平滑"山丘"分支
  return lerp(rg, hl, c.roll)                                              // roll = 0.78·t^0.85
ridgeMean(c)    = (1/96)·Σ_{k<96} ridgeMix(c, (k+0.5)/96)                   // 中点采样，⛔ 端点（首尾同相位会重复计）
crest(i, x)     = c.y − H·( c.amp·(ridgeMix(c, x/W) − c.rmean) + c.amp2·sin((x/W)·c.f2 + c.ph) )
groupRidges(g)  = [ g·sub , min(R−1, g·sub + sub − 1) ]                    // 画布 g 的成员脊线索引区间
groupTopCrest(g,x) = min_{i ∈ groupRidges(g)} crest(i, x)                   // 组内**最高点**（min y）
```

`buildDunes()` 按 `(seed, n, sub)` 生成 **R = n × sub** 道脊，每道带：

| 字段 | 取值 | 为什么 |
|---|---|---|
| `t` | `i/(R−1)`，0 = 最远 … 1 = 最近 | 深度分数，所有按深度的量都从它插值 |
| `g` | `floor(i/sub)` | 所属**画布**索引（分组是全部预算论证的支点） |
| `f1` / `f2` | `lerp(11.0, 1.30, t)` / `lerp(17.0, 2.9, t)` | 横向频率：远密近疏 |
| `s` / `ph` | `hash2(i+3, seed)` / `hash2(i+11, seed)` | ⛔ 各脊同频 = 读成"一条脊的复制" |
| `sharp` | `lerp(3.4, 2.1, t)` | ridged 的 `p` 次幂，**只决定脊有多窄**（见 D14） |
| `roll` | `0.78·t^0.85` | ridged ⇢ 平滑 fbm 的混合，**近景必须是圆丘**（见 D14） |
| `rmean` | `ridgeMean()` | ⛔ 它是"脊形均值"，不减掉的话 `c.y` 不是**平均脊线**位置 |
| `tone` | `mixHex/mixRgb(TONE_FAR → TONE_NEAR, t)` | 沙丘本体是**暗棕**，见 D15 |
| `y` | `lerp(duneTop, duneBot, t^stack · gapK) · H` | `stack > 1` ⇒ **远密近疏**（透视下沙丘场的样子） |
| `amp` | `max(0.004, (gap/H) · ovl)`，`gap` = 到下一道脊的像素间距（末道取到上一道） | 起伏与间距**同源** ⇒ 改层数/改指数都不会突然读平或咬死 |
| `amp2` | `amp · 0.30` | 一次谐波（`f2`） |
| `cols` | `lerp(200, 500, t)` | 烘焙列数：远层本身平，粗步进读不出来 |
| `bandK` | `lerp(0.80, 0.95, t)` | 阳/阴坡着色带 = **整条山坡** |
| `hazePad` | `H·(0.028·(1−t) + 0.006)` | 脊线上方暖雾带高度 |
| `mn/mx` | `layout()` 里在 `step = max(2, W/400)` 上扫出 | 烘焙带高度 = **极值 + 余量**，⛔ 用固定 `×H` |
| `swales` / `ripples` | **只在最近 3 张画布的最前那道脊**（lead-ridge 规则） | 见下 |

⭐⭐ **两个杠杆必须分开记（D13 的核心，⛔ 不写清楚移植者会用 `n` 去加起伏，直接顶穿 4.21 屏）**：

- **`dune.n` = 画布数 = 逐帧 `drawImage` 数 + 铺屏** ⇒ **真预算杠杆**（LOW 5 / MED 7 / HIGH 9）。
- **`dune.sub` = 每张画布内叠几道脊** ⇒ 只吃**烘焙时间**，三档恒 2。
  ⛔⚠️ **「sub 是免费的」只在 `sub` 上调的方向成立，减 `sub` 会更贵。**
  - **`sub` ↑**（画布数不变，每张画布变高幅度不变、只是内部多叠一道脊）：**0 逐帧成本、0 铺屏增量**，纯烘焙时间。
    依据：画布总高 = `Σ(下一组首脊 mx − 本组首脊 mn)`，公式里没有 `sub`。
  - **`sub` ↓**（画布数不变 ⇒ 同样的垂直跨度要由**更少张**画布承担 ⇒ 每张被迫更高）：**铺屏显著上升**。
    ⚠️ **实测（2026-10-14）：`sub 2 → 1` ⇒ 沙丘层 fill `1.1963 → 1.4926`（+0.296 屏），
    HIGH 总铺屏 `3.912 → 4.208`，余量从 0.298 掉到 **0.002 屏 —— 直接坐在 4.21 红线上。**
- ⛔ **反过来说：要加"起伏感"就去提 `sub` 或 `sharp`/`roll`，⛔ 提 `n`。** 提 `n` 是拿铺屏去买层数。
- ⛔ **想省预算时不要动 `sub`**：它是**双向**杠杆，减它比提 `n` 还贵。真要省预算，动 `fx.grain` /
  日晕半径这类不影响几何覆盖的东西，或直接降 `n`。

⚠️ **三个致命的移植坑**：
- **`amp` 是 `H` 的分数，不是像素。** `crest()` 里是 `y − H·amp·(…)`；直接把像素间距塞进 `amp`
  ⇒ 起伏被放大 `H` 倍，`mn/mx` 冲到 **±3000 px**（第三轮首踩）。
- **`DUNES` 必须按索引单调（`y` 随 `i` 递增）。** ⛔ 按**任何**东西排序都会静默破坏三件事：
  遮挡次序（谁盖谁）、`groupRidges` 的连续分组假设、T14 的"每层都要露出"。
- ⛔ **`ridgeMean` 的定义只依赖 `f1 / s / sharp / roll`，⛔ 不依赖 `W/H/y`** ⇒ 改尖度不必重跑 `layout`；
  但改了 `f1/s/roll` 就必须重跑（否则 `c.y` 不再是平均脊线）。

⭐ **lead-ridge 规则**：`lead = (d.g ≥ nG − 3) && (i === groupRidges(d.g)[1])`。
大尺度调子（swales）与风成波纹（ripples）**只给最近 3 张画布的最前那道脊**。
⚠️ 理由是**烘焙预算**：逐脊描边的成本是 `R` 的倍数（`R = 18` 时全给 = 波纹描边 6 万条，
烘焙耗时直接进不了首帧预算）。这三张画布也正是画面上面积最大、最容易读平的沙面。

⚠️ **保留的旧教训（按新结构改写）**：**振幅住在 `DUNES[i]`（`amp`/`mn/mx`），⛔ 不住在任何"表"里** ——
`buildDunes()` 只负责生成**形状**参数（`f1/f2/s/ph/sharp/roll/rmean`），振幅是 `layout()` 才知道的量
（它依赖 `stack/gapK/ovl` 共同决定的 `y` 序列）。早期版本从表里读振幅 ⇒ 恒 `undefined` ⇒ 整片沙丘 NaN 消失（P14②）。

### 4.2 沙丘烘焙（5 道工序，全在烘焙期 ⇒ 0 逐帧成本）+ ⭐ 灯光/暗部尺度规格（D16）

`bakeRune(g, i, y1)` 单道脊的五道工序：① 体块 → ② 阳/阴坡逐列着色带 → ②b 脊线轮廓光 → ③ 大尺度调子 →
④ 风成波纹 → ⑤ 脊线上方暖雾。⚠️ **② 之后所有"沿脊线铺色"的 pass 一律 `clip` 进 ① 的体块路径**：
着色带现在铺满整条山坡（可达 0.1 H），⛔ 靠"脊线上方留 10% 余量"防溢出 —— 溢出会糊到**更远那一层**。

① **体块**：沿 `crest` 折线闭合成面，竖向三段渐变挂在**全沙海共用的一条绝对 y 亮度阶梯**
（`L.horizonY = duneTop·H` → `L.duneFieldBot = 1.02H`）。⛔ 逐层各挂自己那条 `mn → y1`（七踩）：
归一化位置差约 `gap/(y1−mn) ≈ 0.33` ⇒ 两道脊线**相交**处颜色跳一大格，而交点几乎都落在**鞍部**
（那里等高线近乎竖直）⇒ 跳变被读成**一条笔直的竖边 + 一整块贴面**。共用阶梯后：同一个 y 上任何两层**同色**。

⭐⭐ **D16：灯光/暗部的"尺度"必须与"几何"的尺度匹配**（这一节是第三轮十踩里最可移植的一条，
散在原型注释里，⛔ 移植者只抄上一条会重新踩）：

| 量 | 规格 | ⛔ 踩了会怎样 |
|---|---|---|
| 着色带**宽度** | **恰等于步进 `step`**（⛔ `step + 1`） | 每隔 `step` px 一列被双绘（source-over 下 alpha 叠加）= 一条与 `step` 同周期的**竖梳齿**（P10） |
| 着色带**顶边锚点** | **原始 `crest(i, x)`**，与 ① 体块路径同一采样格 | 取平滑后的 `sm`（±2%W ≈ 25 px 平滑窗）在尖脊上**滞后几像素** ⇒ 满屏竖条纹（P11 的复发形态） |
| **朝向** `w` | **连续量**：`w = sigmoid(4.4·(wg − 0.5))`，`wg = (1 − u)·0.5 − lerp(0.34, −0.04, t)` | ⛔ 布尔翻转 `warm = slS < 0` + 保底 alpha ⇒ 每一处符号翻转都是一条 step 宽的**硬竖接缝** = "竖条纹拼布" |
| **alpha 的尺度** | 与朝向**同一个**宽窗 `slS`（±11%W） | `w` 用宽窗而 `mag` 用窄窗 ⇒ **每道细脊的 flank 都被点亮一次** = "砌好的砖墙" |
| **窗宽** | 面积明暗用 `winS = 11%W`（≈ 一座沙丘的半宽），增益 5.5 补回窗宽翻倍造成的衰减 | 窄窗（±2%W 或 ±5%W）在**刀背状窄脊**上仍横跨整道刃 ⇒ `slS` 在十几像素内从 +满 翻到 −满 = 一圈圈竖直贴面 |
| **软饱和** | `mag = \|u\|/(0.30 + \|u\|)`，`soft = \|m\|/(0.34 + \|m\|)` | ⛔ `clamp(…, 0, 1)`：一旦命中就**恒等于 1** ⇒ 一整段坡的 alpha 完全相同 = **平板** ⇒ 交界处导数突变 = 一条笔直竖边的浅色贴面 |
| **逐列阈值分支** | ⛔ 删掉（原先 `if (mag < 0.04) continue`） | 斜率在阈值附近来回穿越 ⇒ 逐列"画/不画"= 竖梳齿 |
| **掠射保底** | `graze = t³·0.26·w`，**只乘在偏阳侧 `w` 上** | ⛔ 做成 alpha 的常数保底（`0.40 + 0.60·mag` 那类）——把 `m→0` 的翻转点抬回 40% 强度 = 把接缝装回去 |

② 的合成式（照抄用，量纲全是像素/归一量）：

```
sm  = (crest(x−win) + 2·crest(x) + crest(x+win)) / 4          // 窄窗平滑，只用于"相对高度"
slS = (crest(x+winS) − crest(x−winS)) / (2·winS)               // 宽窗，**朝向与 alpha 唯一的数据源**
u   = slS · 5.5                                                  // 有符号面斜率（±1 ≈ 一个"整面"）
hf  = clamp((d.mx − sm) / span, 0, 1)                            // 相对高度
shape = hf^1.15 − 0.34                                            // 主项：⛔ 不是 |斜率|（那是描边）
dir = w − 0.5
m  = shape + dir·(0.42 + 0.40·hf) + mag·0.60·dir + graze
wl = sigmoid(7·m)                                                 // 颜色也按 m 连续混：换色发生在 alpha=0 处
α  = soft·( 0.62·litK·(m>0) + 0.80·shadeK·(m≤0) )
```

⭐ `shape`（相对高度）当主项是十踩的关键：**`mag`（斜率）是线的属性**，它在脊线两侧都取峰值 ⇒ ② 铺出来的
永远是"紧贴剪影的一条亮带 + 一条暗带" = 描边 ⇒ 沙丘身体内部一点明暗都没有 ⇒ 整片读成一叠薄片（P19）。
参考图恰恰相反：明暗铺在**整张坡面**上，驼峰亮、坡脚暗，一个来回只翻一次。
`dir` 只留三成权重（次要的左右不对称），`mag` 退居辅助。

②b **脊线轮廓光**：只留一道**薄亮刃**（`rimH = max(3, 0.008H + 0.020H·t)`，
α `= 0.30·litK·hf^0.90·(0.55 + 0.45w)`，**沿脊走**），⛔ 不再配脊下阴带 ——
九踩当时是为了在"② 只剩两大面"时冒充体积；十踩把主项换成 `shape` 后，阴带退化成**第二条描边**，
与亮刃一起把每道脊框成一条"线"，正是薄片观感的另一半。⛔ 也不许把亮边挂到 ① 体块渐变的 stop 0 上
（那条渐变住在**绝对 y** 阶梯上 ⇒ 层内矮一点的驼峰全是中间调 = 层内读平）。

③ **大尺度调子**：几团超扁（`ry/rx ≈ 0.2`）暖/冷径向渐变破掉"平"（⛔ 圆团）。
④ **风成波纹**（只给 lead-ridge）：**平行于脊线**的整幅色带 —— 每条带按**体高分数** `f ∈ [0.12, 0.88]`
定位（`y = crest + (y1 − crest)·f`）⇒ 带跟着脊线起伏；由 `fbm` 掩膜断续
（`a = clamp((m − 0.42)/0.34, 0, 1)`），暗槽描在 `+0.55·lw`、亮脊描在 `−0.62·lw`。
⛔ 随机短划（首轮就是"散落的小 dashes"，读成划痕）；⛔ 各脊同相位（会横向串成一条整梳 = 印刷网点）。
⑤ **远脊暖雾**（`haze = fx.haze·(1 − t)`，`hazePad` 内）：一层线性渐变把脊线**化入**天幕，让远脊变成剪影刀边。

### 4.5 孤烟 = 烟丝链（⭐ 需求 ①②⑦ 的全部实现都在这两节）

**柱轴**（解析，⛔ 粒子系统）。⚠️ **第三轮换了锚点函数**：旧的 `beaconTopY / beaconX` **已不存在**：

```
L.srcRidge   = layerOf(P.comp.smokeSrc)              // 深度分数 → 脊线索引（四舍五入 ⇒ 滑杆读回来的就是真正生效的那道）
L.srcLayer   = DUNES[L.srcRidge].g                   // 该脊所属的**画布**索引
L.smokeX     = P.comp.smokeX · W
L.smokeBaseY = groupTopCrest(L.srcLayer, L.smokeX) + 0.010H     // ⭐ 落在画布顶边**之下** ⇒ 该画布后画时把烟根吃掉
L.smokeH     = max(20, L.smokeBaseY − P.comp.smokeTop · H)
x(u,t,ph) = L.smokeX + swayPx(u,t,ph) + jx·puffR(u)
y(u)     = L.smokeBaseY − u·L.smokeH + jy·puffR(u)·0.4        u ∈ [0,1)
```

⚠️ 删掉烽燧后烟根落到**更近的沙脊**上 ⇒ **烟柱比旧几何高约 15%**，`smokeH` 的分母变了 ⇒
**同幅摆动的倾角随之变小** ⇒ T5 阈值必须**收紧**（10° → 6°），⛔ 不能为了变绿而放宽。
⭐ 迁移坑：`groupTopCrest` 与 `crest` 是**不同的函数、不同的失败模式** —— ⛔ 绝不能用单条脊
（取低了骆驼/烟根会整个埋进画布里，取高了则遮挡链失效）。

**摆动 = 行波**（⭐ 第二轮返工的核心，P3）：

```
swayRaw(u,t,ph) = u^1.7 · [ sin(2πt/19 − u·lag1 + j) + 0.45·sin(2πt/7.3 − u·lag2 + 0.61j + 1.7) ]
j = ph · phJit                       // phJit = 0.20 ⇒ 逐粒只留 20% 的去相关
swayPx = P.smoke.amp · W · swayMul · swayRaw      amp = 0.0082, lag1 = 0.80, lag2 = 1.45
```

- 两个**不可通**拍频（19 s / 7.3 s）⇒ 峰值可达 1.45 但永不变周期（T2 判 `rawMax ≥ 1.40`，
  ⛔ 单正弦：峰值只有 1.00 ⇒ 判据当场变红）。
- ⛔ **逐粒随机相位**：那是"每粒各摆各的"，柱子读成闪电/Z 字。相位必须**随高度连续滞后**
  （`−u·lag`），`ph` 只作**微量去相关**。
- ⚠️ 滞后与包络**都吃倾角预算** ⇒ 加滞后必须**同时下调 amp**（0.0110→0.0082）。
- 逐粒横向抖动 `jx = (hash2(i·11+3, lap) − 0.5)·0.42·jitK`（返工前 0.7）：
  ⚠️ 抖动量级必须 **≪ 摆幅**。

**尺寸 / 浓度 / 朝向**：

```
puffR(u)   = r0·H·(1 + grow·u^1.25)          r0 = 0.0150, grow = 0.50   // 纵向 = elong × 宽 = 2.55
α(u)       = alphaK·0.1·(u/0.05)^0.7·(1−u)^1.30                          // 根部出烟、顶端散尽
tilt(u,t,ph) = atan2( (swayPx(u+0.02) − swayPx(u−0.02)) / 0.04 , smokeH ) + rot
rot = (hash2(i·23+7, lap+4) − 0.5)·0.45       // 每粒自身倾角噪声
```

- ⛔ 烟丝竖直贴图 ⇒ 柱子弯了丝不弯，读成"一根根插着的筷子"；tilt 一律吃**柱切线**。
- ⭐ `α(1) = 0` 是**结构性**的（`(1−u)^1.30`），T7 判两端归零 + 单峰 + 方向转折 ≤1。
- **变体分配** `variantOf(i, lap, V) = (i + 2·lap) mod V` ⇒ 相邻两粒之差 `1 + 2Δlap` 模 6 **不可能为 0**
  ⇒「相邻永不贴同一张」是**构造保证**，⛔ 运气。
- **回绕**：`u ≥ 1 ⇒ u −= 1, lap += 1`，并按 `hash2(i, lap)` **重抽** `ph`/变体
  ⇒ 同一格每圈长得不一样，⛔ 同一张贴纸一直爬。**粒子数守恒**（T3）。
  ⚠️ 抖动住在**槽位偏移** `of`（±17% 槽宽），⛔ 逐粒速度差 —— 速度差会随圈数累积成断档。
- **芯丝线** 2 条（MED/HIGH）：沿**柱轴**（`ph = 0`）取 `u ∈ [0.06, 0.72]` 的 14 段折线，
  横向各偏 `(s − (strands−1)/2)·puffR(u)·0.26` ⇒ 让"直"读得出来。
  ⛔ 画到 `u = 1`（硬撑到顶会**分叉成 Y**，P2）；⛔ 各点吃逐粒随机相位（P3 的同一根因）。
- **逆光暖边**：`u < rimMax(0.62)` 的粒再叠一张暖色丝，横向偏 `side·rimOff·r`（`side = sign(sunX − x)`），
  `r·0.80`、纵stretch `×0.78`、alpha `al·rimA·ember`。
  ⭐ `rimOff` 必须**大于芯丝足迹**（0.95），否则暖边整条落在白烟底下，只是把烟**加亮**而不是**加边**（P4）。
  T8 判"暖边质心必须在朝日一侧"**且**"最高只到 `u = rimMax`"。
  ✅ 已确认干净（不必再动）：暖边**不会读成第二条烟** —— 烟柱横截面 alpha 是**单峰**的。

**烟丝位图烘焙**（`bakeWisp`，128×128，6 变体 × 中性/暖边 = 12 张）：
3 根丝（主丝 + 左右两条子丝，宽 ×0.62/×0.55、alpha ×0.74/×0.64）各 22 颗软盘，
沿**摆动竖直曲线**排布（摆动幅度随 `s` 增大 ⇒ 根部直、梢部散）；
盘半径 `w = 0.30·wmul·(0.35 + 0.65·sin(πs)^0.55)`，三段径向渐变（0.17 / 0.09 / 0）；
最后 **4 遍错位叠印**（`(0,0)0.50 / (−2,1)0.28 / (2,−1)0.18 / (0,3)0.14`）做**无 filter** 柔化。
⇒ 全部代价付在 `onEnter`，逐帧每粒只是 1–3 次带旋转的 `drawImage`。

### 4.6 驼队

```
CAR.cross = 1.24 / pace                        // 走完 1.24 W（含两侧余量）的秒数
starts[i+1] = starts[i] + cross + idle0 + rnd()·(idle1 − idle0)   // idle ∈ [40, 80] s，方向逐波交替
head(t) = (−0.12 + 1.24·p)·W  (dir>0)   |   (1.12 − 1.24·p)·W  (dir<0)
footY(x, jit, bob) = groupTopCrest(L.carLayer, x) + h·H·[ occl·(0.62 + 0.38·jit) + bob ]
visible(jit, bob)  = clamp(1.06 − off, 0, 1.06) / 1.06,  off = occl·(0.62 + 0.38·jit) + bob
```

- ⭐ **脚线跟着"所在画布的可见顶边"**（⛔ 一条水平线 ⇒ 骆驼飘在沙丘前面）；遮挡 = 该画布在驼队**之后**画（D4）。
- ⛔⛔ **`groupTopCrest` 必须是组内最高点（min y），绝不能取单条脊**（这是**不同的函数、不同的失败模式**）：
  取单条脊 ⇒ 取低了腿要么浮空、要么整只埋进画布消失；取高了则遮挡链直接失效。
- `occl = 0.520`；6 帧步态 `bob = 0.035h·sin(2πt/3.4 + 帧相位)` ⇒ 起伏本身就会把露出比推出定值，
  T9 因此判**区间**而 ⛔ 定值（`[0.40, 0.85]`）。
- ⚠️ blit 偏移**必须由精灵自己的 `sole` 行推出**：`drawImage(c, −cx·sc, −sole·sc, w, h)`。
  返工前写成 `−h + sole·sc` ⇒ 整只骆驼画到脚线**以下**，被后画的画布全埋 = **P5「驼队整批消失」**。
- ⚠️ 剪影形状（双峰为**全剪影最高两处**、粗颈、头顶低于前峰、货捆破左右对称、尾、
  所有部件 alpha **恒 1.00**）是 P6 的修法，⛔ 重烘成另一形状就退回"一群鹅"。

### 4.7 浮沙与调色

`veil`：`0.9W × 0.11H` 横向**无缝** fbm 带（周期噪声用 `cos/sin(2πi/w)` 保证接缝处取值相同），
逐帧 2 层各 2 张平铺（第二张补右缘），漂移 `driftPx = wind.base·W·(1 + 0.33·gust)·(1 + 0.5·bass)`，
alpha `0.30·sandK·(1 − 0.35i)`。Kotlin 侧用 `ImageShader(TileMode.Repeated)` ⇒ 每层折成 **1 op**。

⭐ `grade`（**第三轮已按 D15 改过两个数**）：

```
a = gradeOn · fx.vignette · smoothstep(0.62, 1.10, r) + hash2(i,j)·fx.grain·0.55     // vignette 0.34 → 0.10
RGB = 暖棕 (46, 26, 20)                                                            // ⛔ 紫黑底 (44,20,26)
```

一次 `putImageData` 烘成一张（全屏、**逐像素只依赖 `(i,j)`** ⇒ 天然可分帧），逐帧 1 blit。
`P.gradeOn` 开关 = **降级杠杆 ①**（按钮 `bGrade`，也是 P11 用来销疑的 A/B 开关）。
⚠️ **有 alpha**（`d[k+3]`）⇒ Kotlin 侧 ⛔ 不能用 `RGB_565`（见 §三）。

## 五、逐帧图元预算（TV 安全线）

**计量口径**（页面 `op(cat, screens, n, collapse)`，按符号名定位）：`OPS` = 图元条数、`FILL` = 铺屏
（该组 op 的**面积和 ÷ 一屏**）、`COLLAPSE` = Kotlin 侧会折掉的条数（只有一处：`veil` 平铺第二张 →
`ImageShader(TileMode.Repeated)`）、`PROF[cat]` = 逐类别分解。T13 判 `ΣPROF ≡ OPS` 且 `Σfill ≡ FILL`
（口径漂移当场检出）。⚠️ 已知漏记见 **P21**。

### 5.1 真实结构 = **按组循环 + 组内条件分支**（⛔ 不是扁平图层表）

> ⚠️ 上一版是一张扁平图层表（底层 4 段 / 沙丘 3 段 / 水面反光柱 / 烽燧+余烬…），其中
> 「水面」「烽燧」两行已失效、「沙丘 3 段」已变成 `nG` 张画布。真实调用序是：

```
renderFrame(t):
    blit(B.sky)                        → op('天幕渐变', 1.0)          // 全屏锚 ①
    drawSun()                                                             // 日晕 ×haloLayers + 日盘（第二次 fill）
    for gi in 0 .. nG-1:                                                // nG = dune.n，⛔ 不是脊线数 R
        if gi == L.carLayer:  drawCaravan(t)                             // 驼队
        if gi == L.srcLayer:  { drawEmber(t); drawSmoke(t); }            // 烟根暖光 + 孤烟
        drawDune(gi)                                                     // 该组画布 blit（吃掉腿 / 吃掉烟根）
    drawVeils(t)
    drawGrade()                                                          // 全屏锚 ②
```

⭐⭐ **这个条件分支本身就是 D4 遮挡语义的闸门**：画布 `gi` 在驼队/烟根**之后**画 ⇒ 它的顶边把它们盖掉。
错序的两种死法正是 P5 的两种表现（**骆驼浮在沙上** / **驼队整批消失**）。⛔ 它不是一个"顺手的顺序"，
K5 必须**逐字断言**这个 `if` 的存在与位置（判据形态照 E47 T12：**要求错误的那条路不存在**）。
⚠️ 也注意：循环的是**画布数 `nG`**，⛔ 不是脊线数 `R` —— 逐帧成本只与画布数有关，这正是分组的全部意义（D13）。

| 组 | 形态 | 条数来源 | 铺屏来源 |
|---|---|---|---|
| 天幕 | 1 blit | 恒定 | **1.000 屏**（全屏 op 是本效果的"安全锚"，见 5.3） |
| 日盘 + 日晕 | `haloLayers` 次 `halo()` 的 `arc.fill` + 日盘 **1 次** `arc.fill` + **1 次**同 arc 的竖向 `fill` | `fx.haloLayers` + 1（日盘的两次 fill 只记 1 个 op，⚠️ P21） | 日晕按 `π·rad²`；日盘按 `2πR²` |
| 沙丘画布 | 每张 1 blit | `dune.n`（5/7/9） | 各自画布总高 × W |
| 驼队 | 每峰 1 次 blit（在场时才计） | `caravan.camels` | 峰面积 × **露出比** |
| 烟根暖光 | 1 个小径向渐变 `fillRect` | 恒定 | `r·2 × r·2` |
| **孤烟** | 每粒 ≤3 次带旋转 blit（外晕 / 芯丝 / 暖边）+ `strands` 条细线 stroke | `puffs` × 类别 + `strands` | 单粒足迹很小（`2r × 2r·elong`） |
| 贴地浮沙 | 每层 2 张平铺（Kotlin 折 1） | `fx.veils` | 带宽 × W |
| 调色 | 1 blit | 恒定 | **1.000 屏** |

### 5.2 预算论证（结论）

- **HIGH 3.91 屏 / 96 op（Kotlin 折叠后 94）vs E44「明月」真机已验收的 4.21 屏 / 217 op ⇒ 余量 0.30 屏（7.6%）。**
  LOW 3.39 屏 / MED 3.69 屏给低配设备留余量。
  ⇒ 本主题**不需要** E47 那种"超预算待裁决"的豁免，但 ⛔ **经不起再多一层全屏级图元**。
  ✅ 这三个数现已固化为 harness 的 **B1/B2/B3 预算上限断言**（进 `process.exitCode`，已验证有牙齿），
  ⛔ 不再是"只打印不断言"的裸数字。⚠️ 余量之所以从 3.89 被啃到 3.91 再救回，是第四轮放大日盘的代价（P26）。
- ⚠️⚠️ **铺屏是深度累加的 overdraw，不是"唯一像素"**：同一像素被 N 张沙丘画布覆盖就记 N 次。
  读 §十 的类别表时若按"面积并集"去理解，会**大幅低估** HWUI 侧的代价。沙丘画布合计占 1.196 屏
  （总 3.87 的 **31%**），而**唯一像素**只有约 0.6 屏 —— 两者差的那部分就是被埋掉的。
- **成本重心与 TV 安全线的方向相反**：**op 数**绝大部分落在烟（外晕 + 芯丝 + 暖边三类合计约 65 op
  却只占 0.138 屏），**铺屏**绝大部分落在沙丘画布 + 两张全屏（天幕 1.000 / 调色 1.000）。这两件事分别
  对应两条不同的红线：
  1. **创维 API 22 的 HWUI 崩溃形态**是「大量互不相连的**小矩形**、且没有全屏 op 打底」
     （项目记忆 `project-baseline-tv-hwui-limits`）。本效果**恒有两个全屏 op**（`sky` + `grade`）垫在首尾，
     烟粒是**带旋转的位图 blit** 而非小矩形填充 —— 与已验收的 E44「明月」（缕贴图同形态）同类。
     ⛔ **但"降级杠杆 ① 砍掉调色层时，天幕那张全屏 op 仍在"这条护栏必须保留**：砍了两个全屏锚之一，
     剩下的那张必须真的是全屏（不是半屏带），否则风险面性质就变了。
  2. **铺屏是跨效果唯一可比的数**（op 数不可比：一条 Path 里 30 段与 30 张贴图在 HWUI 侧代价完全不同）。
- ⭐ **第三轮在预算上唯一的改善**：日晕的填充形状从「半径 rad 的方形」改成「半径 rad 的圆」
  ⇒ 按 `π·rad²` 计量，2 层 0.561 屏 ⇒ **3 层 0.259 屏**。**更便宜且更有层次**
  （裁决要的是层次，不是亮度 ⇒ ⛔ 提高日晕强度去"更亮"，`treble` 只缩放 `sunGain` 1.00–1.21）。
  方形的四个角是纯透明像素，白付 21% 铺屏（`4r²` vs `πr²`）。
- ✅ **删掉水面反光柱（N 段小矩形、1 次 fill）后，HWUI 的"小矩形雷区"风险面变小**，这条方向是对的。

## 六、音频映射（纯氛围克制，⛔ 频谱条 / ⛔ 节拍闪光）

Kotlin 侧输入 = `AudioSmoother` 之后的**线性**四通道 `bass/mid/treble/energy` + `section`；
⛔ 吃 gamma 显示通道 `spectrum`（E44/E46 的同一条红线）。式子在页面的 `worldState()`（按符号名定位）：

| 通道 | 消费点 | 式子 | 增益 | 观感 |
|---|---|---|---|---|
| `bass` | 烟上升速度 | `risePx = smoke.rise·H·(0.55 + kRise)`，`kRise = 0.90·bass` | 0.90 | 鼓点重 ⇒ 烟抽得快 |
| `bass` | **烟根暖光**亮度（原「烽墩余烬」，第三轮改名） | `ember = 0.70 + 0.50·bass`，暖边 alpha `·= ember` | — | 脊线上的暖色明暗 |
| `energy` | 摆动幅度 | `swayMul = 0.50 + 0.85·energy` | 0.85 | 响 ⇒ 烟被吹歪一点 |
| `treble` | **只缩放 `sunGain`**（⛔ 不再驱动反光柱 —— 水面已删） | `sunGain = 1 + 0.35·0.60·treble` ⇒ 1.00–1.21 | 0.60 | 高频 ⇒ 日盘亮一档（⛔ 不是"水碎光变多"） |
| `mid` | 浮沙浓度 | `sandK = 0.40 + 1.10·mid` | 1.10 | 人声段 ⇒ 沙雾起 |
| `section` | 远脊暖雾 | `haze = fx.haze·(0.80 + 0.50·section)` | — | 段落级慢变，不做逐拍 |

**无声必须仍然活着**（T11 的判据形状）：`gust` 与 `driftPx` 有**纯时间基线**，`swayMul` 是
`0.50 +` **而不是**纯音频项 ⇒ 静音时烟仍按基线摆、沙仍漂。实测（§十）：无声 900 帧 `max|Δ通道| = 0.0e+0`
（映射**不漂**）而基线摆幅仍有 **13.9 px**（@1600 宽）；有音 90 帧 `max|ΔswayMul| = 0.4420`（映射**活着**）。
负样本：把 `swayMul` 写成纯音频项 ⇒ 无声 alive = 0.0 px = **画面定格**，当场变红。

⚠️ **刻意克制**：摆幅、暖光、落日增益的幅度都定在"看得出生意、看不出在跟着鼓点跳舞"的量级
（判读时刻的最大摆幅与四路极值由 `beatScan()` 现算，§十）。所有者对 E47 的同类判读是
"摆幅 8.82 px 是否克制" —— E48 同量级，真机验收清单里保留这条肉眼裁决。

### 7.1 ⭐ 分帧烘焙：这是**既定需求**，不是 contingency

- **烘焙实测 ~1332 ms**（HIGH，热跑）是 E46 定下的 **24 ms/帧**预算的 **55 倍**，冷启动可达 **7.1 s**。
  ⇒ ⛔ **一次烘完必然掉帧/卡死**，分帧烘焙是**需求**，不是"若超预算再说的预案"。
- ⭐ **单个沙丘组就装不进一个 24 ms 片**（由档位斜率反推每组 ~130 ms，占烘焙 ~90%）
  ⇒ **粒度必须到"列块"**，不能按"一张画布"切。
- ✅ **可行的依据**：`bakeRune` 的每一道工序要么 **x 可分离**（② 的逐列明暗、④ 的波纹描边 ——
  都是 `crest(i, x)` 的函数，列与列之间无耦合），要么 **y 可分离**（① 的体块渐变、⑤ 的暖雾渐变）
  ⇒ **列块烘焙是精确且无缝的**，不需要任何缝合 trick。唯一需要重叠的是 `winS` 依赖的邻域
  ⇒ 相邻列块重叠 **±`winS`**（±11% W）即可避免 P10/P11 那一类接缝。
- ⭐⭐ **烘焙顺序必须由远及近倒序**（`nG−1 → 0`），**与作者的循环顺序相反**：
  否则半烘状态下会先画出 `dune0` 而后面什么都没有 ⇒ 观感就是"首帧半幅"，正是要避免的失败模式。
- ⭐ **`grade` 最后烘**：它是顶层叠加，且按构造就是**逐像素循环**（只依赖 `(i,j)`）⇒ 天然可分帧；
  但它必须**最后**完成，否则会在半成品画面上盖一层暗角。
- ⭐ **首帧内容** = 天幕 + 日盘 + 最近 **1–2** 个沙丘组（照 E46/E47 已验收的做法）。
  仓库里的先例：`SnowCedarBakes.UNIT_PX_CAP = 24000`（单元像素上界）+ `BAKE_BUDGET_MS = 24L`（时间预算），
  E46 的 `TripodFogBake.BAKE_UNIT_PX_CAP = 24000` / `BAKE_BUDGET_MS = 24L` 同形。
  ⛔ 首帧空白、⛔ 一次烘完阻塞主线程。
- ⚠️ **首帧墙钟的验收数字：待真机实测确定**（原型侧只能给量级：冷启动 3741/6671/7135 ms、热跑
  791/1166/1332 ms，**冷热差 5 倍**，⛔ 不能当设备数字用）。K3 的判据建议写成：
  「从 `onEnter` 到**首帧可见画面**的墙钟 ≤ 100 ms，且 ≤ 2 个 24 ms 预算片」——
  写成**相对预算**而不是绝对毫秒，跨设备才可比。⚠️ 具体阈值由 K3 实测后回填本节。

## 八之二、证据的元问题：判据的三类、已发现的盲区、判读闭环本身的缺陷

> ⭐ 这一节记录的是**证据体系本身的性质**，不是某一条实现缺陷。它决定"14 条全绿"到底意味着什么。

### 8.2.1 现有 14 条判据**全部是结构判据**，没有一条能证伪"画面读起来对不对"

T1–T14 测的是「摆动函数达到峰值」「alpha 包络单峰」「驼峰露出比例在区间内」「相邻重叠率 ≥1.8」

### 8.2.4 ✅ 判读闭环已修（2026-10-14）：撞时刻的根因不是"取了同一个峰"，是**两条积分路径 dt 不一致**

- **原病灶**：「余烬峰」与「升速最快」撞在同一 `t=137.43 s`，两张截图 **SHA-256 逐字节相同**；
  7 张判读帧两两平均通道差只有 0.09–0.10（8-bit 尺度）。
- ⭐ **真正的根因（比"取峰撞车"深一层）**：`beatScan` 按 `1/30` 推进，而 `seek` 按 `1/60`；
  `smoothAudio` 是**一阶平滑器** ⇒ dt 差一倍 ⇒ 同一个 `t` 在两条积分路径上的 `risePx` **差一个量级**
  （实测 `beatScan` 报 4.02 px/s，`seek` 渲染出 43.2 px/s）。
  ⇒ **"取峰值的那一刻"和"实际渲染的那一帧"根本对不上号**，撞车只是它的表征。
  ⚠️ 这条对 E46/E47 同形：任何"先扫描再回放"的判读位，两个函数的 dt 必须同源。
- **修法**：① `beatScan` 与 `seek` 同源同 dt；② 两个判读位**互斥**（`SEPARATE = 6.0 s`，
  先定余烬峰，再在离它 ≥6 s 之外取升速峰，⛔ 不是随便挑一帧）；③ driver 加 **SHA-256 去重**（重复即报错）
  与 **`phasediff`**（两两平均通道差）。
- **实测结果**：新 `a2` 余烬峰 `t=91.85 s`、新 `a3` 升速峰 `t=2.55 s`，**相隔 89.30 s**；
  七帧 21 对**全部可区分**，范围 **0.074 – 0.189**，最接近的一对是 `a2↔a6`（0.074，两帧都无驼队、只有摆动相位差）。
- ⚠️ **残留的诚实保留**：`a2` 与 `a3` **都**报 `余烬=1.0` / `升=43.2 px/s` ——
  `ember` 与 `risePx` 都在很宽的区间里**顶到天花板** ⇒ 两个时刻虽然相隔 89 s、画面确实不同，
  但**「余烬峰」和「升速最快」仍未各自隔离出自己的量**。这是**音频映射饱和**的性质，
  解它会动 T11 的映射契约 ⇒ **属产品取舍，不属观感取舍，待所有者裁决**（见 P24）。

## 九、决策记录（D1–D16）

- **D1 柔化只有两条路**：径向渐变 + **烘焙期错位叠印**（4 遍 `±2 px` 半透明重绘）。
  ⛔ `ctx.filter` / `shadowBlur` / CSS blur ⇒ Compose Canvas 无对应能力（约束 ①）。
  真实度令（需求 7）据此划边界：⛔ 禁的是**逐帧拿圆盘当烟**，✅ 允许**烘焙期**用软盘堆出一张**丝状纹理**。
- **D2 烟 = 烟丝链**（一维回绕队列，常驻 `Float64Array`：`u/ph/of/lap/vr`），⛔ 粒子系统。
  理由：需求是「**一条**」，任何"多股/扩散/新生成"的粒子语义都与"直"冲突；且 flat 数组让 T1（逐位复现）
  与 T3（守恒）成为**可判**的数学式，⛔ 对象池与 GC 抖动。
- **D3 摆动 = 行波**（相位随高度连续滞后），⛔ 逐粒随机相位（P3）。
  代价说清楚：滞后与包络都吃倾角预算 ⇒ `amp` 必须同时下调，T5 的阈值是这条取舍的裁判。
- **D4 驼队遮挡 = 图层序**（画布 `carLayer` 在驼队之后画），⛔ 裁腿、⛔ 干脆不画腿（需求 5）。
  ⭐ 第三轮后"跟哪条线"的答案也变了：脚线跟 `groupTopCrest(carLayer, x)`（**组内最高点**），
  ⛔ 不是 `crest('mid', x)` 这种单条脊。
- **D5 驼队偶发 = 时刻表**：`starts[i+1] = starts[i] + cross + idle0 + rnd()·(idle1−idle0)`，方向逐波交替。
  ⛔ 逐帧随机判"该不该出现" ⇒ 既不可 1800 s 复现（T10 要判波数与空窗），也会读成"闪烁"。
- **D6 沙脊做成解析函数** `crest(i,x)`，⛔ 噪声位图。
  收益：烘焙带高、驼队脚线、烟根锚点、layout 极值扫描、**T14 的每层露出**、T12 切日比例

### 10.2 ⚠️⚠️ 两条会被误用的口径警告（⛔ 读数前先读这两条）

- ⚠️ **烘焙墙钟是"量级论证"，不是设备数字**：热跑与冷启动之间差 **5 倍**
  （LOW/MED/HIGH 冷启动可达 **3741 / 6671 / 7135 ms**，而热跑只有 **791 / 1166 / 1332 ms**）——

- ⚠️ **铺屏是深度累加的 overdraw，不是"唯一像素"**：同一像素被 N 张沙丘画布覆盖就记 N 次。
